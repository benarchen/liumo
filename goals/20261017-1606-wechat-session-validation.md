## 授权、数据与系统边界

### 可以自主推进的工作

- 后续实施时，在既有授权内读取项目与公开资料、核对当前 Mac 微信版本和受支持的正常访问入口，修改相关项目文档与自研验证代码，补充必要测试、脱敏示例和证据。
- 优先既有组件及标准库。新增项目隔离依赖必须确有必要，先核对维护、安全与替代成本；不安装全局依赖，不运行复制的上游代码。
- 新模块先在项目规则登记职责，再写入 `validation/`；测试与脱敏样本分别放 `tests/`、`examples/`，不搭建通用代理平台、爬虫框架、插件体系或完整产品界面。
- 经已明确授权的访问方式，对两个目标号做有限、只读样本验证；普通采集、诊断、回归和产物检查由 Agent 完成，不让用户手抄参数、修改 JSON 或重复运行已通过测试。

### 初始未授权及当前授权例外

- 不默认读取微信本地数据库、钥匙串、进程内存、聊天记录或无关公众号会话；“微信常驻在线”不构成提取这些数据的授权。
- 时区、休眠、后台任务和其他系统改动仍不在范围内。临时用户级、限定 `mp.weixin.qq.com` 的 CA 信任、当前服务 HTTPS 代理切至 `127.0.0.1:8899` 及指定两篇最小凭证采集已由用户后续明确批准；仅一次、最多 10 分钟，仍须先满足完整基线、恢复控制和日志保护。
- 不注入或修改微信、不绕过证书固定、验证码、付费或访问控制，不关闭 TLS 校验，不更换账号规避限制，不借浏览器替代协议或权限绕过环境门禁。
- 不使用公共代理，不将凭证交给在线 exporter、RSS、中转或其他外部服务；不购买、部署、公开发布，不提交／推送 Git，不修改 guixu。
- 沿用原 Goal 的单 Agent 执行边界，不委派子 Agent。
- 不启用正式订阅，不下载历史文章正文。列表返回较旧条目仅用于判定覆盖边界，不能因此启动历史归档。

### 数据保存

- 真实阅读凭证只进入获准的项目 `.auth/wechat/`，每号隔离、最小字段、当前用户权限；不得放入命令行参数、普通日志、截图证据或对话。具体写入与轮换方式在 C1 授权范围内列明，不能覆盖来源不明的既有文件。

### C1 的临时凭证实验设计要求

1. 把“只读系统现状”“创建项目内程序”“信任证书”“切换代理”“真实采集”“恢复配置”分别列出，标清哪些在现有授权内，哪些还需要明确授权。证书与代理的批准不得被解释为读取全部微信数据。
2. 如果采用代理，只监听回环地址；尽可能限定目标域、文章入口和两个目标号。其他域流量不解密、不记录；不得宣称系统代理对其他应用绝无影响。同域请求若必须解析后才能区分目标号，应明确这一接触范围，不能将事后丢弃说成从未接触。无法满足授权范围就不执行该方案。
3. 先记录原代理与证书状态，设置短时、可取消的实验窗口；仅恢复本次明确修改的项，不删除既有证书、不覆盖并行用户修改。不因退出异常而遗留系统代理指向已停止的端口。自动恢复不可保证时，执行前必须提供可操作的恢复办法。
4. 匹配目标请求后只提取已核对必需字段，避免整包保存 Cookie、请求、响应或抓包文件。网络端点、方法、请求头与字段来源逐项对照，不以“看起来相同”代替核对。
5. 凭证不转发第三方。若使用项目隔离的成熟网络组件，仍自行实现留墨的匹配、状态与保存逻辑，不导入 exporter 或 wxdown-service 的业务代码。

### C3、C4 的通过门槛

- 自动发现必须支持近期多篇与覆盖范围内补查；仅最新一篇不通过。初始样本最多每号 3 页、串行、页间至少 2 秒；扩大范围前先用实际缺口说明必要性，不能为了返回全历史终页无限翻页。
- 分别记录接口原始时间字段的含义、原文时间、时区和核对结果。只有核对过的原文时间才可用于启用边界；不能修改 `time_verified` 来让回放测试通过。
- 明确采样窗口起止与分页是否有序。窗口覆盖需有边界证据；“读到一篇旧文章”本身不足以证明没有遗漏。技术样本之外不保存启用前文章正文。
- 留言、回复按稳定 ID 核对；当前程序仅覆盖 elected_comments，其他当次可见区域出现时不得静默忽略。此前用户截图的 15／33 条是历史观察，不用来强制匹配新的实时数量。
- 不主动追踪归档完成后的新增评论。第一次成功快照冻结；恢复失败部分时需保留既有结果和时间差，避免静默覆盖首份成功归档。
- 正文／配图、API 评论快照和原页截图需记录各自时间与来源关系。截图必须来自正常原页，不通过注入接口数据、移动操作栏或删除附属区域制造“完整”效果。
- 真实超长单图、真实回复跨页等条件若样本未覆盖，应写明；构造大样本证明逻辑和限制处理，不能补作真实通过证据。

## 阶段验收与 Goal 完成判定

### 本阶段成功条件

- 两号凭证取得与使用有真实证据；初始必要配合后可重复自动取得，无需用户手抄或每日反复开文章。若续期尚未观察到，必须保留其未验证状态，不能宣称长期无人值守。
- 两号近期多篇发现、分页／窗口覆盖与原文时间有对应证据；自研程序不靠最新一篇回退满足要求。
- 两篇样本的正文与本地图可离线核对，评论／回复快照范围可解释；含相应区域的单张原页截图通过实际检查。部分成功不能写成完整成功。
- 敏感数据边界、失败恢复、已有归档保全及必要自测通过；如有获准系统改动，恢复也需真实检查通过。
- 下列交付物完整且互相一致，尚未覆盖的事件与限制明确列出。

### 不满足成功条件时

仍须交付已取得的代码、失败证据、实际可行范围和必要取舍，不能只留一份计划。可以完成某个研究／构造检查点，但不得把本阶段真实项改成通过；原 Goal 继续未完成。连续两轮同方向失败后停下机械重试，复核一手资料、正常对照与字段差异，再决定下一步，不无限扩大路线。

本阶段成功也不自动关闭首个 Goal：C6 必须回看原施工清单，包括真实增量、实际网络恢复、设备休眠／唤醒等剩余项。仍缺验收证据就保留状态；不安装系统调度来强行补验。不把模拟断网或时间推进当设备实测，不为了测试退出用户微信或改变其登录状态。

Goal 生命周期遵循当前工具规则：不新建、不自行设 paused；恢复后的阻塞按新一轮实际情况审计，不能沿用旧三回合计数。同一必要条件连续至少三个 Goal 回合无法解除、且没有可推进工作时才设置 blocked；只有原目标实际验收完成才设置 complete。工具服务与本地文档状态分别如实记录。
