## G1：归档完整性检查与损坏恢复

**拟创建目标：**「补齐 RSS、手动及历史归档的离线完整性检查，修复历史损坏条目无法重试的问题，交付保留旧数据的显式恢复能力及证据。」

### 接口、范围与检查点

允许修改 `liumo/history.py`、`manual.py`、`store.py`、`__main__.py`，新增 `liumo/integrity.py` 与 `liumo/repair.py`；仅在必要处调整归档器。前者负责公共文件／元数据只读核对，后者组织单篇修复与安全图片复用，不另建抓取、调度或账号框架。

- [x] **G1-A：先复现。** 构造一份历史 complete 记录，分别制造 Markdown 缺失、图片哈希不符，证明现有 `--retry` 仍不进入归档器。保留失败断言及原因，修复后同一测试转为通过。
- [x] **G1-B：统一只读校验。** 规划 `verify --scope rss|manual|history|all`，以账本登记的快照为起点核对目录、元数据身份／类型、正文和配图哈希、相对图片引用；对未登记尝试单独标为未索引，不自动入库或删除。仅离线读取，不改文件、账本、基线，不打开浏览器。空范围输出明确 empty，不能假报已核验若干文章。
- [x] **G1-C：明确结果契约。** 分开输出账本状态与 `integrity_status`，后者至少区分 intact、missing、corrupt、unverifiable；旧快照字段不足不得当完整。重复图片引用不等于损坏；路径越界、符号链接、坏 JSON、身份不匹配明确失败。输出检查时间和数量；退出码 0 为所检条目通过或明确空范围，2 为发现异常／未核实／无法完成检查。
- [x] **G1-D：显式恢复。** 规划按 scope 和文章 key 定位的 `repair` 入口；没有选定条目不得隐式修复全库。RSS／历史优先复用已保留输入，手动原文继续现有正常浏览器路径。可复用且哈希匹配的本地图优先复用，缺失资源才按原有边界获取。成功产物先完成并校验，再更新对应账本指向；原快照与尝试记录保留。不把校验命令自动升级成修复。
- [x] **G1-E：修复历史重试。** 在判定候选前核实 complete 文件；显式 retry 可纳入损坏项，普通只读核验不降级或改写账本。新尝试失败时保留旧记录和异常原因，不标完整；连续运行不得重建已经修好的快照。恢复来源不足时明确不可恢复，不用空正文代替。
- [x] **G1-F：状态与历史入口。** `status` 继续保持轻量，明确它报告任务状态，完整性结果须显式 verify；不在每分钟 tick 全库扫描。history 的帮助与运行回执标明专项验收状态，未经 G3 通过不能伪装已交付功能。

### 自测与验收

新增 `tests/test_integrity.py`、`tests/test_history.py` 的对应用例。全程使用隔离路径与注入的抓取函数，禁止测试修改正式账本。

| 场景 | 必须断言 |
| --- | --- |
| 三类完好快照、空目录、合法重复配图 | 结果准确；无网络、无文件修改；空范围计数为 0 |
| 缺正文／图片、改字节、坏元数据、身份冲突、旧字段不足 | 不能标 intact；原因与受影响文件可定位 |
| `../`、绝对路径、符号链接、超限元数据 | 拒绝越界读取／写入，固定错误类别不泄漏原始敏感值 |
