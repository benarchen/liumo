## 环境问题的处理顺序

1. 已授权的项目内工作先连续完成，不把网络或浏览器问题泛化成所有命令都要用户执行。
2. 通过当前客户端受支持的权限入口核对有效配置，集中解决必要网络、子进程与回环能力。用户配置中的自动审核不等于权限开放；受管会话也可能覆盖用户配置。当前只读检查未确定这些限制的具体配置来源，不能承诺修改某一项即可解决全部问题。
3. 用户可在 Codex CLI 的 `/permissions` 入口查看可用权限配置；如由宿主或管理策略限制，需通过对应设置或管理员调整。只启用项目所需能力，不默认取消整个沙盒，也不将审批设为 never 当作网络修复。本轮未修改用户配置或请求全盘访问。[官方权限说明](https://learn.chatgpt.com/docs/sandboxing) 已于 2026-10-19 核对，说明审批与沙盒权限分别控制。
4. 配置确有变化后只复核此前失败的必要能力；确认环境具备运行条件后，再按实施指令继续 V1。没有配置变化时不反复测试同一失败，也不要求用户重复回复“授权”或到普通终端代跑受限操作。
