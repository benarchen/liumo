# 安装信任锚的离线对照：已授权实施

本次独立授权实验已结束：安装后的 17 项约束与后续独立撤销均取得有效证据；原 120 秒自动收尾未通过，不标记整体验收成功。当前无需用户操作，不重装或重跑。分项见 [现场证据](/Users/chenge/project/liumo/evidence/feasibility/installed-anchor-live.json) 。

## 需要决定的变更

此前实验使用用户级 SSL 信任，并通过 `security add-trusted-cert` 的 `-s mp.weixin.qq.com` 设置策略字符串。候选改为使用带 critical NameConstraints 的新根证书：许可目标 DNS 子树、排除其子域和全部 IPv4／IPv6；仍仅用户级 SSL 信任，但不设置旧 `-s` 字符串。

这不是已经证明安全等价的替换。当前证据仅涵盖 OpenSSL 内存 TLS 与 macOS 显式根验证；安装后或其他客户端可能有不同的根约束处理。临时用户信任可被同一用户的其他应用看到，即使本实验不访问网络；不能声称它已被系统保证只对目标域生效。本次已取得该范围的独立授权，不沿用之前实验授权。

建议先做以下无网络、无代理的安装前后对照；通过后再单独准备微信实验。无需前置或刷新微信、扫码、提供凭证或重启应用。

## 固定范围与执行顺序

1. 独立且不可复跑的私有目录 `.auth/wechat-capture/anchor-scope-session/`，使用当前既有重叠锁。先核对前五次系统实验均已恢复、停止；不得改写旧目录。创建唯一 CA 名称和证书指纹，不复用归档证书或原采集 CA。
2. 使用已有 cryptography 签发短时新证书，只将改进候选安装到当前用户登录钥匙串；无约束根和朴素根只用于内存／显式根对照，绝不安装。根与叶证书私钥仅留签发子进程内存，签完公共证书后先结束签发子进程，再进入安装步骤，不写私钥文件；安装对象仅为公共根证书，不导入私钥。
3. 安装前验证候选指纹不存在；使用 `security verify-cert -v -L -R offline -p ssl -n HOST -k LOGIN_KEYCHAIN -c LEAF` 检查同一组构造叶证书。该阶段不传 `-r`，不以传入根覆盖系统信任判断；没有 AIA／CRL URL，不访问网络。只指定当前登录钥匙串，不枚举其他账号证书／信任配置。安装前须取得可解释的不信任结果，内部错误或未知输出停止。
4. 在写入恢复日志后，仅执行该新公共根的用户级 `add-trusted-cert -r trustRoot -p ssl -k LOGIN_KEYCHAIN CA`，不带 `-s`。双时钟与独立收尾进程覆盖最多 120 秒的信任窗口；终端退出或中断触发恢复。任何系统权限提示只由用户确认，不申请管理员／系统级信任，不自动重试失败安装。
5. 在相同参数下验证 17 个场景：目标及大写形式接受，12 个范围外证书、错主机／过期／错误签名共 15 项拒绝。读取固定数字诊断，不把任意非零返回当有效拒绝，不将 CT 提示当根因。逐项结果必须能与有效的显式根正负对照配对；边界逃逸、未知结果或超时立即结束并撤销。
6. 无论结果如何，撤销本次用户信任并仅按本次 SHA-256 指纹删除新公共证书；回读该证书已不存在，并确认原本有效的目标叶证书恢复为可解释的不信任。撤销验证将公共根作为第二张 `-c` 链证书提供，仍不传 `-r`，防止“仅缺少链证书”掩盖遗留信任；安装前也核对同一形式。该阶段不触碰代理，因此没有代理恢复操作。恢复不明确即停止推进，保留本次私有恢复计划，不声称成功。

整个实验不启动监听器或代理、不访问微信／外部接口、不读取旧 `.auth` 中的账号凭证、不改其他信任项或系统配置。独立进程无法保证断电或自身被 SIGKILL 后即时清理，因此要先交付仅作用于本次证书的恢复入口；不能承诺绝对自动恢复。
